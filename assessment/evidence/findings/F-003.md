# F-003 | P1 | BUILT-WRONG | seam / data integrity

**Impact:** The fit/gap report's "Required" column renders blank — the API emits `expected_level`, the web reads `required_level`. The report *looks* complete; the required-level data is silently dropped. The `is_override` ✏ indicator is also dead (never emitted).

**Evidence (static contract):**
- API emits `expected_level` — `api/app/services/fit_gap/engine.rb:58-67`, returned verbatim by `api/app/controllers/api/v1/portfolios_controller.rb:200-210`.
- Web reads `required_level` — `web/src/types/index.ts:130-137` (`SkillComparison.required_level`), `web/src/components/fitgap/ComparisonTable.tsx:50` (`LEVEL_LABELS[c.required_level]`).
- Web reads `is_override` — `web/src/components/fitgap/ComparisonTable.tsx:56`; the engine computes `overridden` (engine.rb:83) but never emits it in the comparison hash.

**Expected:** The comparison object must use one agreed field name (`expected_level`) end-to-end, and carry an override flag if the UI displays one.

**Root cause:** systemic pattern P-α — hand-written per-controller `*_json` hashes (no serializers) plus loose `any` types on the web allow field-name drift to ship unnoticed.

**Caught by:** planned — contract test asserting the fit/gap comparison shape, plus a web component test asserting the "Required" cell renders a level.

**Status:** open
