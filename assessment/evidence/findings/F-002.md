# F-002 | P1 | BUILT-WRONG | authz / tenant isolation (object-level)

**Impact:** An assessor of one tenant can export (or override) another tenant's portfolio by guessing its integer id. `Portfolio`, `PortfolioSkill`, `FitGapReport`, `CoverageMap`, and `TranscriptTurn` have no `tenant_id` and are reached by global `find`.

**Repro (local, dev DB):**
```bash
# acme's portfolio id=1 (created via tmp/setup_repro2.rb)
TOKEN=$(curl -s -X POST http://localhost:3001/api/v1/auth/login \
  -H 'Content-Type: application/json' -H 'X-Tenant-Scheme: test-corp' \
  -d '{"email":"admin@example.com","password":"password123"}' | python3 -c 'import sys,json;print(json.load(sys.stdin)["token"])')
curl -s -H "Authorization: Bearer $TOKEN" \
  "http://localhost:3001/api/v1/portfolios/1/export?format=json"
```

**Observed** (full output in `evidence/findings/F-002-repro.txt`): a `test-corp` token returned acme's portfolio with HTTP 200, including `"competency_summary":"acme candidate summary"`.

**Expected:** Every child record must be reachable only within the caller's tenant (scoped through its parent session/assessment), or carry its own tenant check.

**Root cause:** `TenantScoped` is column-driven — only models with a `tenant_id` column are scoped. Child models lack it, and controllers look them up by bare id: `api/app/controllers/api/v1/portfolios_controller.rb:150-160` (`Portfolio.find(params[:id])`), `api/app/controllers/api/v1/portfolio_skills_controller.rb:50-55`.

**Caught by:** planned — RSpec request spec asserting cross-tenant portfolio access is rejected.
